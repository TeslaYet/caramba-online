## Security headers

Implemented in `next.config.ts`:

- `Content-Security-Policy` with `default-src 'self'`. `connect-src` adds the Supabase origin from `NEXT_PUBLIC_SUPABASE_URL` when that variable exists at build time, including the matching `wss:` host, so login and realtime are not blocked.
- Google ad hosts are added only when `NEXT_PUBLIC_ADSENSE_CLIENT_ID` is set at build time.
- `frame-ancestors 'none'`, `X-Frame-Options: DENY`, `nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`, HSTS, `Permissions-Policy` with camera, microphone, geolocation, and payment disabled.
- `form-action` allows Stripe Checkout and Billing hosts so a future form post is not the only path; the current code navigates to the URL Stripe returns.
- `script-src` still allows `'unsafe-inline'` because the current Next.js app relies on it. Tightening that further is a separate change and was not done here, to avoid breaking the game.

`payment=()` does not block a full-page redirect to Stripe Checkout. It would block the Payment Request API / some embedded payment surfaces. Hosted Checkout is the intended path.

## Logging

`lib/server/errors.ts` logs the error name and message, with `Bearer` tokens stripped. It does not log the request body, cookies, or Stripe secrets. Chat text is not written to the log by the report route. Vercel’s own request logs can still contain IP addresses and URLs. Set their retention in the Vercel project.

## Age

No age gate was added. GDPR Article 8 is about whether a child can consent alone to an information-society service offered directly to them. It is not a rule that every card game must ask for a date of birth. Chat, public ratings, advertising, and payments are the facts that can change that answer. A lawyer should decide whether the terms set a minimum age. Inventing one in the database would not, by itself, satisfy a child-directed advertising duty.

## International users

The implementation is EU-first: consent before advertising scripts, GDPR-style export and deletion, French mentions légales draft. That is a reasonable baseline for a French operator.

- UK: the UK GDPR and PECR are separate. A certified Google CMP that covers the UK is the practical advertising fix. A UK representative is a different question and depends on whether you target the UK without an establishment there.
- US state laws (CCPA/CPRA and others): MAY APPLY if you are “doing business” there and pass the thresholds. The current audience and revenue are unknown. Do not add a US “Do Not Sell” page until you know you are in scope. The advertising refuse button is still the right technical default.
- Other countries: availability of the website is not the same thing as targeting. If you advertise in a country or take payment there, revisit that country’s rules.

## Entitlements

`profiles.entitlement` is `FREE`, `AD_FREE`, or `PREMIUM`. `entitlement_source` is `default`, `manual`, or `stripe`. `entitlement_expires_at` and `stripe_customer_id` were added in `supabase/migrations/004_compliance.sql`.

The trigger `protect_profile` rejects entitlement changes unless the database role is postgres, supabase_admin, or service_role, or the request carries the server secret (`private.request_authorized()`). The profile page cannot send an entitlement. A Stripe webhook is server-side. A friend grant is SQL you run in the Supabase SQL editor.
